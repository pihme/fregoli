Fregoli

Self-evolving web application on a Cordis kernel, named for Leopoldo Fregoli, the quick-change artist. One process, many appearances: plugins load and unload without restarting Node.

#What it is

Fregoli is a web application an agent can rewrite while it is running. Instead of editing files and restarting the process, capabilities are Cordis plugins that are mounted and unmounted in a live Node process. The name comes from Leopoldo Fregoli (1867–1936): one performer, many appearances, no restart of the show.

On start you get a canvas on port 8080 and an assistant chat in the lower right. Chat goes to the Grok CLI over ACP when grok is on PATH, otherwise to an in-process stub. Grok receives an MCP server that lets it observe the page, load and unload plugins, highlight elements and wait for the user to click.

The CLI is always fregoli in full, never freg.

#Current status

Status as of 26 September 2026 · main@33bc4a9

Everything here is asserted by tests that pass on main: in CI all 25 tests of npm test pass, and a local run on Node 22 passes 24, skipping only the Docker image build for lack of Docker. The kernel boots with the web, agent and stock assistant plugins, and GET / serves the welcome canvas with the assistant in the lower right. Chat over POST /chat reaches an ACP agent when one is spawned, with a timeout cancelling and resuming the session, and falls back to an in-process stub otherwise. A plugin mounted at runtime draws on the canvas without restarting Node, while a broken plugin never becomes ACTIVE and leaves the canvas alone. The page bridge and MCP tools work: observe_page returns the live DOM, a highlight followed by a user click comes back as a tool result, and reload_page is a one-shot command. A saved fregoli.json can omit the assistant, --assistant brings the stock one back, --help and --version answer, and the Docker image builds in CI. The latest release is fregoli/v0.3.1 (25 September 2026).

Chat through the real Grok CLI is not covered by tests: the ACP tests use a stand-in agent, and without grok on PATH replies come from a stub. The CLI knows only --help, --version and --assistant, so port 8080 and host 127.0.0.1 are fixed when it is started that way, and there is no authentication on the web UI or the HTTP API. Running inside Hermetarium is documented, but no test starts the image behind a wall, and releases are source tarballs only: the package is private and no prebuilt image is published. Five issues are open. The server binds only to 127.0.0.1, so the documented docker run -p 8080:8080 is likely unreachable; the Dockerfile leaves out the shipped plugins, fregoli.json and the Grok skills; the docs call fregoli --assistant although nothing puts fregoli on PATH; --version reads only FREGOLI_VERSION and does not show the release tag; and it is unverified whether the node:22-alpine image has the ip tool Hermetarium needs to set the default route.

#Key concepts

Cordis kernel

The kernel is Cordis (npm cordis). Every capability is a plugin, or “fiber”, that can be mounted and disposed at runtime.

Web plugin

HTTP on TCP 8080: the canvas, the assistant slot, a JSON API and the page bridge (DOM snapshot, highlight, user click).

Agent plugin

Spawns grok agent --always-approve stdio and speaks ACP. Falls back to a stub without grok. Unloading the plugin kills the child.

Assistant plugin

Lower-right chat panel. A separate plugin: replaceable and removable. fregoli --assistant forces the stock one for that start.

Loader gate

Mounts extra plugins from fregoli.json or POST /load. A plugin whose apply fails does not become ACTIVE and does not replace the canvas.

MCP tools for Grok

src/mcp.ts: list_plugins, load_plugin, unload_plugin, observe_page, highlight, wait_click, reload_page.

#Getting started

Needs Node 22+. For a real agent, the Grok CLI on PATH (authenticated via Grok CLI login or XAI_API_KEY).

git clone https://github.com/pihme/fregoli.git
cd fregoli
npm ci
npx tsx src/cli.ts              # http://127.0.0.1:8080/
npx tsx src/cli.ts --assistant  # force the stock assistant UI
npx tsx src/cli.ts --version

Run the tests (the merge gate):

npm test

Container image (Hermetarium is a recommended habitat, not a requirement):

docker build -t fregoli:local .
docker run --rm -p 8080:8080 fregoli:local

Saved config lives in fregoli.json in the process working directory:

{ "assistant": true, "plugins": [] }

Full CLI and HTTP reference: usage guide.

#Architecture & layout

The agent plugin spawns grok agent --always-approve stdio and passes the MCP server spec in ACP session/new; Grok starts src/mcp.ts with FREGOLI_URL pointing back at this process. Shipped plugins (plugins/shipped/) mount at boot; runtime plugins via fregoli.json or POST /load.

PathContents
src/cli.ts, src/boot.ts, src/kernel.tsCLI entry, boot sequence, Cordis context

plugins/shipped/Canvas plugins shipped with the repo; every *.ts mounts at boot
